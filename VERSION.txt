strategy_hub_bot - CLEAN HUB BUILD (owner only)
Built: 2026-10-24 SGT (see the zip file name for the time).

WHAT IT IS: one bot where YOU build the strategy per pair in the Strategy Hub tab, from boxes you tick. Nothing is preset.
- First install is fully BLANK: no starter values. The setup page holds only pair-level settings (candle timeframe, isolated margin, poll seconds, Telegram, price-feed stale seconds, OKX trigger type). Fill them and press Confirm.
- A pair with NO saved plan will NOT start.
- Hub screen = LAYOUT 2 (2026-10-23): strategy name + account at the top, menu of 8 functions on the left (Pair & chart, Indicators, Combine & flip + hold rule, Entry, Max loss, Stop loss (trailing), Take profit, Shadow mode), the boxes of the open function on the right with a short explanation beside each, Save and Execute at the bottom. The first 4 functions are needed by every strategy; the other 4 are picked. Execute = save + start the pair (after a confirm).
- Flip = CLOSE, FLAT, CHECK FOR CHANGES IN RULES, ELSE OPEN OPPOSITE IF NO CHANGE.
- Candle colour only for Heikin Ashi / Renko. Signals from HA/Renko, trades on normal candles.
- The old Hull fields are gone from the setup page and the Add pair form. The strategy lives only in the Strategy Hub boxes. (The old Hull code is still in the files, unreachable.)

SHADOW MODE in the Hub (new): after a real trade closes in profit and the tracker reaches a new high, the next N trades are PAPER only, following the plan's entry rules, wait, flip / hold, size and max-loss stop. Paper trades do NOT simulate take profit or the trailing stop. The tracker follows every real result, even when the box is not ticked; turning the box off ends a running shadow period.
FIXED BASE AMOUNT (new, 2026-10-23): ENTRY SIZE has a method choice. 'Allocation % of balance' works as before. 'Fixed base amount (grows with the last closed total)': you key in the base in USDT (margin; leverage stays in its own box; the position is amount x leverage). First trade = the base. After each FULL close the next entry = the total of that trade (its entry amount + every fill added up: TP1/TP2/TP3, SL, trailing, BE, net of fees), never below the base. Trend and against-the-trend each have their own base; ONE running total for both. No cap, no reset. The running total is saved on the server and survives a restart. Paper (shadow) trades never change it.
MAX LOSS (new own box, 2026-10-23): choose what the loss is measured on: % of available balance (as before), % of entry amount (the margin before leverage), or a fixed $ amount. Older saved plans keep working as '% of available balance' and 'Allocation %'.
AT LEAST N (new, 2026-10-23): ENTRY and FLIP / EXIT combine each have ALL, ANY or 'At least N' (you key in N; N cannot be more than the indicators ticked on that side).
LOCK-OUT % (new, 2026-10-23, fixed base only, optional): next entry = the entry just closed + that % of the trade's profit; a loss comes off in full; the base is still the minimum. Empty = off (the whole total is carried).
EMAIL ALERT ON MARGIN (new, 2026-10-23): when an entry needs more margin than the available balance at that moment, an email (and Telegram) is sent, once per candle. It never blocks or changes the entry. Needs the SMTP settings and the alert email.
ENTRY WAIT WARNING: the dashboard pops up 'Delay in entry up to N candles' when you set Entry wait above 0. Default stays 0 (no delay).
STRATEGY NAME: a label saved in the plan (renaming it does not count as a rule change).
TREND / COUNTER-TREND SIZING in the Hub (new): chart close vs an EMA you choose decides which size (allocation + leverage) an entry uses. Off = one size.
NOT PROVEN on a real exchange: TP limit orders, trailing-stop moves (use Binance testnet / OKX demo first).
Order-id prefixes ('hullbot_' / 'hullbotokx') are unchanged on purpose, so orders already on an exchange are still recognised.
Old build notes in docs/ keep their old names (history only).
Handoff for a new chat: docs/HANDOFF_READ_FIRST.md
INFO ICONS (new, 2026-10-23): an "i" beside every field; click it for the full explanation pop-up. Texts: HELP table in app/static/dashboard.html. Check: tests/browser_info_icons_check.py.
STOP LADDER (new, 2026-10-23): Max loss (last line of defense), Stop Loss (new), Trailing Stop (Step / lowest low-highest high / moving average), Take profit in % of ATR or % of price movement, Allow Mid-Trend Re-entry (off by default). Nearest stop on the exchange (stop-limit for Stop Loss / Trailing Stop, stop-market for Max loss); the others watched live by the bot. NOT PROVEN on a real exchange - test on testnet / demo first. KIV list: docs/HANDOFF_READ_FIRST.md.
ONE TAB PER FUNCTION (2026-10-24): the Hub menu has 13 tabs; Hold rule is a menu pick.
RENAME (2026-10-24): "MA 1 vs MA 2" is now "MA Crossover" (name only).
SHADOW + CHART (2026-10-24): the shadow is a paper copy of the whole plan that runs all the time (also while real trading is paused: trades off, Stop, STOP ALL); Chart tab = real candles on top, shadow tracker below.
STRATEGY LIBRARY (2026-10-24): "Save to library" keeps a strategy by name (date/time SGT, pair, timeframe); "Library" lists Saved + automatic History (old versions kept every time a pair's plan is changed or removed); Load fills the Hub for any pair (nothing saved until Save / Execute); Delete only after a confirm. "Remove plan from pair" (kept in History first; refused while trading or a trade may be open). Kept on the server (DATA_DIR/strategy_library.json).
MAIN (2026-10-24): in Indicators, "Main for ENTRY" and "Main for FLIP" (your choice, can differ, or none). The Main has to happen; the other ticked indicators show confluence (Combine). None = as before.
FLIP + INSTANT (2026-10-24): "FLIP / EXIT" renamed "FLIP". A Hub pair wakes 0.5 s after its candle close (not at its next poll), so a flip or entry starts at once. Not measured on a real exchange yet.
PART CLOSED BY HAND (2026-10-24): a part of a Hub trade closed outside the bot is now recorded in the Ledger and in the fixed base amount total (price and fees from the exchange fills; mark price as an estimate if not found). Not proven on a real exchange yet.
TRAILING "BEGINS" (2026-10-24): Step Trailing Stop start "Begins at a price move": Begins when the price moves / Stop goes to (0 = breakeven) / Then moves every. E.g. SL 2 ATR, at +0.5 ATR to breakeven, then trails every 0.25 ATR.
ANALYSIS ON THE HUB (2026-10-24): Walk-Forward and Monte Carlo replay the pair's own Strategy Hub plan (same engine as the shadow, TradingView candle order, your commission / slippage on every fill, trades off when Shadow mode is picked). Binance history over 1,500 candles is fetched in pages.
RSI / MACD CONDITIONS (2026-10-25): RSI: Above / below level, Overbought / oversold, Divergence. MACD: Histogram above / below 0, Zero line. Older plans keep what they did.
MORE OPTIONS (2026-10-25): Candle colour "Strong candle only", MA "Pullback to MA (bounce)", "ADX must be rising", "ATR must be rising", Volume "Average without the signal candle". All off / not chosen by default.
TICKS + COUNTER TREND (2026-10-25): Conditions are ticks (tick 1 or more, all must agree) on MA 1, MA 2, MA Crossover, RSI, MACD. Counter trend decided by: EMA length or any indicator with a side (CTREND column in Indicators = the same setting). Counter-trend size 0 = no counter-trend entry.
FLIP (2026-10-25): "Close only" removed. A flip always closes, goes flat, checks for rule changes and enters the new side. Old plans with "Close only" now flip.
FLIP TAB (2026-10-25): 3 Yes / No boxes - Same as entry, Same as hold rule, Same as entry wait (Yes = follows the main settings; new plans Yes; older plans keep what they did). "Combine" renamed "Indicator Combination" everywhere.
HOLD RULE DEFAULT ON (2026-10-25): a new strategy starts with the Hold rule picked and its ADX level at 25 (editable). Saved plans keep what they have.
ENTRY WAIT TAB (2026-10-25): "Candles Wait" (starts 0), "Fresh Reversal on First Trade" (starts ticked), "No Mid-Trend Re-entry" (starts ticked).
ENTRY SIZE TAB (2026-10-25): Size method is "tick one" (only its boxes show), Counter-trend size and Margin alert are their own sections, the counter trend is decided only by the CTREND tick, and a "Next entry" line shows the next entry's size.
RENAME (2026-10-26): "Max loss" -> "Max Loss per Trade" (name only).
STOP LOSS TAB (2026-10-26): Stop Loss always in the menu; save allowed without it; no SL or SL not worked out = the trade still opens + Telegram/email alert to set it manually; Measured on adds Fixed $ amount, Structure (swing low / high), Chandelier, Moving average; optional Time stop.
BREAK-EVEN TAB (2026-10-26): new tab after Stop Loss - After TP (1, 2, 3) and / or After ATR (100 = 1x ATR): the Stop Loss moves to the entry price.
AUDIT FIXES (2026-10-26): stop-limit gone through and not filled -> market close after 2 s; no leverage / margin-mode calls while a position is open (OKX 1x on restart fixed); margin mode set at every hub entry; no entry on the same candle after a trailing / time-stop close (shadow, Analysis, Pine). Blank Pine script added (pine/).
TP MEASURED FROM (2026-10-27): Take profit has a new choice 'Measured from': 'Entry price' (as before; a plan without the choice means this) or 'Signal candle close' (the normal close of the candle the entry is made on; the ATR is that candle's ATR). Nothing removed. Left empty = Entry price. Shadow, Analysis and the Pine script already count from the signal candle close. Entry wait above 0: the candle the entry is made on. A TP price already behind the market at the fill is still sent as a reduce-only limit (the exchange fills it at once). Tests: tests/test_hub_tp_from.py, tests/browser_tp_from_check.py.
TRAILING STOP 4th TYPE (2026-10-28): 'Signal candle high / low +/- ATR'. Long: signal candle low minus the distance; short: signal candle high plus it. Distance (% of ATR, 100 = 1 ATR, starts at 100, editable) uses the ATR of the signal candle, fixed for the trade. At every candle close the level is worked out again from the candle that just closed and only ever moves nearer (into profit), never further from the entry. It rests on the exchange like the other trailing stops; the live price through it closes the trade. Stop Loss and Max Loss stay behind it. Same in the shadow, Analysis and the Pine script (the Pine script is not compiled here). Nothing removed. Tests: tests/test_hub_trail_candle.py, tests/browser_trail_candle_check.py.
PRESETS (2026-10-28): new 'Presets' button next to 'Library' in the Strategy Hub, with two ready-made strategies 'HMA Flip' and 'MACD Cross'. A preset holds ONLY rule choices: NO NUMBERS at all (every number box is empty for the owner; only the form's own starting boxes keep their start: Hold rule ADX, Candles Wait, Trailing Stop distance). Load = a new form first, then only what the preset says; the pair's timeframe and margin mode are not touched; nothing is saved on the pair until Save or Execute. A preset is read only (frozen); to change one, Load it, edit it, Save to library under your own name. No server change. The preset data is in app/static/dashboard.html between the markers PRESETS-BEGIN and PRESETS-END.
PRESETS UPDATE (2026-10-30): the HMA Flip preset now has the Trailing Stop type 'Signal candle high / low +/- ATR' picked (owner's word). Still no numbers; the ATR length stays empty. Nothing else changed.
LOSS LIMIT + COOLDOWN (2026-11-01): two new Strategy Hub tabs (Cooldown after a loss, Loss limit) and a 'Loss limits' box for one account / all accounts. They only stop a NEW entry; an open trade is never touched. No numbers anywhere by default, not in the presets. Tests: tests/test_hub_loss_cooldown.py, tests/browser_loss_cooldown_check.py.
RSI CROSSES ITS OWN MA (2026-11-01): RSI has a 4th condition 'RSI crosses its own MA'. Long = the RSI line crosses UP through its own moving average, short = it crosses DOWN through it (the average is taken of the RSI line, not of the price). Average type: SMA, EMA, WMA, HMA or ALMA (ALMA also has Offset and Sigma). You key in the average length and N (signal stays on); the RSI Length is the RSI's own. Nothing is filled in for you, not in the presets. Can be ticked together with the other RSI conditions (all ticked must agree). Also in the Pine script (STRATEGY_HUB_BLANK.pine, RSI group). Tests: tests/test_hub_rsi_ma_cross.py (36), tests/browser_rsi_ma_cross_check.py (28). Not proven on a real exchange; the Pine script was not compiled in TradingView here.
LOSS LIMIT IN % (2026-11-02): every Loss limit (this strategy, one account, all accounts together; daily and weekly) can now be a USDT amount OR a % of the account balance at the start of that day / week (you can key in both: the first one reached stops the entries). The bot saves the account balance at the first check after 00:00 SGT (Monday 00:00 for the week); the % is worked out once from it, so the limit stays the same USDT number all day. If the bot sees the account late in the period, the balance saved is the balance then minus what the ledger shows as closed since the start. For 'all accounts together' the % is taken of the saved balances of the accounts added up (an account with no Strategy Hub pair running saves none). Only used when a % is keyed in; it reads the account balance (read only), never touches a trade. No numbers by default. Tests: tests/test_hub_loss_limit_pct.py (50), tests/browser_loss_cooldown_check.py (49). Not proven on a real exchange.
