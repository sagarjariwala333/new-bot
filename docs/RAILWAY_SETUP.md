# Railway setup — for the IT person

**Rules for this job**
- Deploy into the **owner's own Railway project** (the owner invites you, or shares a screen).
- You never need, and must not ask for: trading settings, exchange API keys, the dashboard password,
  or the encryption key. The **owner types those in themselves.**
- Do not edit the code. If something does not work, tell the owner what failed.
- When the deployment works, the owner removes you from the project.

> Railway behaviour described below was written from Railway's documentation and has NOT been
> run against a live Railway project by the person who prepared this package. Treat step 7 as the
> real test, and report anything that differs.

## 1. Create the service
1. In the owner's Railway project: **New > GitHub Repo** (push this folder to a private repo of the owner's) or **New > Empty Service** and deploy this folder with the Railway CLI.
2. Railway reads `railway.json` (build with Nixpacks, start command `python run.py`, health check `/healthz`, restart on failure, **1 replica**) and `.python-version` (Python 3.12) and installs `requirements.txt`.
3. **Keep the service at exactly one replica.** The app keeps state in one process and refuses to run trading from a second one. Do not enable horizontal scaling or "PR environments" with the same volume.

## 2. Add a persistent volume (required)
- Service > **Volumes** > add a volume, mount path **`/data`**.
- Without it, the encrypted exchange keys, saved settings, ledger, trade state and the tracker (all-time high, shadow state) are wiped on every redeploy.
- The app checks this itself: on Railway, if `DATA_DIR` is not inside the attached volume, it refuses to start trading, shows a red banner explaining why, and sends an alert. The dashboard still opens.
- `railway.json` sets `drainingSeconds` to 120 (a JSON **number**, not a string) so a stopping deployment has time to finish and release its lock before Railway force-stops it.

## 3. Variables
Service > **Variables**. Names and meanings are in `.env.example`.

| Variable | Who sets it | Value |
|---|---|---|
| `HOST` | IT | `0.0.0.0` |
| `DATA_DIR` | IT | `/data` |
| `COOKIE_SECURE` | IT | `true` |
| `DASHBOARD_USERNAME` | owner | e.g. `admin` |
| `DASHBOARD_PASSWORD` | **owner** | owner's own password |
| `MASTER_ENC_KEY` | **owner** | generated by the owner (command in `.env.example`); the owner keeps a copy |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | **owner** | optional |
| `SMTP_*`, `ALERT_EMAIL_TO` | **owner** | optional |

`PORT` is injected by Railway - do not set it.
If the owner leaves `DASHBOARD_PASSWORD` blank, a random one is printed once in the deploy log. Avoid that: anyone who can read the log would see it.

## 4. Public URL
Service > **Settings > Networking > Generate Domain** (HTTPS). Open it: the login page should appear.

## 5. Start / stop / restart / monitor
| Action | Where |
|---|---|
| Start / redeploy | Deployments > **Redeploy** (or push a commit) |
| Stop | Deployments > **⋯ > Remove** / or Settings > pause the service |
| Restart | Deployments > **⋯ > Restart** |
| Logs | Deployments > **View logs** |
| Health | `GET https://<domain>/healthz` returns `{"status":"ok",...}`. Point an external uptime monitor (UptimeRobot, healthchecks.io) at it. |

After a redeploy the dashboard may briefly show a red banner saying another instance may still be running: the app will not trade while an old copy's heartbeat is less than 60 seconds old. The new process keeps retrying every 5 seconds and starts trading BY ITSELF once the old one is gone (usually within about a minute) - nothing needs restarting. If it is still blocked after 3 minutes the owner gets an alert; tell the owner and do not try to work around it.

Restarting the service is safe for the app itself, but it stops every running pair's loop until the app is back up; running pairs resume on boot. **Do not restart while the owner has real positions open unless the owner agrees.**

## 6. What you can and cannot check
You can check: the build succeeds, `/healthz` is OK, the login page loads over HTTPS, the **Default Settings** tab shows blank fields, the app survives a restart with the volume attached (the owner's login still works afterwards).

You cannot check, and should not try: Add Pair, Start, or anything that trades. Those need the owner's Default Settings, which the app deliberately refuses to work without. Exchange connectivity is only exercised when a pair is started, so the **owner** verifies that on a Binance testnet / OKX demo account after filling in the settings.

## 7. Hand-over checklist
- [ ] `/healthz` returns OK on the public domain
- [ ] Volume mounted at `/data`, `DATA_DIR=/data` set
- [ ] One replica only
- [ ] The owner has typed `DASHBOARD_PASSWORD` and `MASTER_ENC_KEY` themselves
- [ ] The owner can log in
- [ ] The IT person is removed from the Railway project and from any GitHub repo, and the owner rotates any token the IT person saw

## 8. Owner's steps after hand-over
1. Log in. Open **Default Settings**. Fill in every field for Binance and/or OKX. Press **Confirm Default Settings**, review, confirm. Enter your alert email.
2. Add a **testnet / demo** account with testnet/demo API keys and create a pair. Start it. Watch the log. Check the exchange shows the stop order.
3. Only then add real accounts. Turn **Live trading** ON when you are ready. It is OFF by default and real-money accounts cannot start while it is OFF.
